# Phase 0 report — feasibility of browser-level E2E for the extension

Date: 2026-09-21 (revision 2 the same day, after Codex review). Throwaway spike in a temporary directory (nothing added to any repository except this report). Tools: `playwright-core` 1.63.0 with its matching Chromium 153.0.8010.12 (revision 1243), headless (new headless), one temp profile per run.

## Verdict per condition (from `dev-test-automation-plan.md`, phase 0)

| | Condition | Result |
|---|---|---|
| a | Extension loads in a persistent Chromium context; service worker reachable | **PASS** — worker up, extension id is the fixed `ekejcladpfhmaghllolijpiakhcffpmp` |
| b | Allowlist `context.route` serves the mock for windows created *by the extension* | **FAIL as planned.** The extension-created DeepSeek window loaded the **real** `https://chat.deepseek.com/` (CloudFront error page); the route did not see it and nothing was aborted. **Alternative evaluated: browser-level host mapping** (`--host-resolver-rules="MAP chat.deepseek.com 127.0.0.1:PORT, MAP fixture.test …, MAP * ~NOTFOUND, EXCLUDE 127.0.0.1"`) + a local HTTPS server with a test certificate + `--ignore-certificate-errors`: the extension-created window received the mock. **Measured boundary (revision 2):** mapping alone did **not** stop a request from the page to *another loopback port* (a second local server got a hit), i.e. it would expose the owner's local dev servers. Adding `--proxy-server=http://127.0.0.1:9 --proxy-bypass-list="chat.deepseek.com;fixture.test;mail.test;<-loopback>"` (a dead proxy for everything except the mock hostnames) blocked it: 0 hits, while the mapped hosts still worked. Unmapped hostnames, an unroutable IP literal and a LAN IP literal were blocked in both settings (0 server hits for the LAN probe). **Claim, deliberately narrow:** for the fixed probe set above, requests reach only the local mock/fixture server; the server log records what it received. This is not a firewall (host rules and a dead proxy are not a sandbox; WebRTC/UDP and similar were not tested) and is only claimed for the trusted mock and fixture pages the tests serve. |
| c | Unmodified `sidepanel.js`, opened as a tab in the fixture's window, drives the assistant | **FAIL as planned.** `isSidePanel()` requires `!sender.tab`, so a panel opened as a tab has every message refused (`assistant.status` → `undefined`, state stays "Assistant not started"). **Alternative evaluated and PASS:** open the *real* Side Panel with `chrome.sidePanel.open({windowId})` from a click on an extension page (Playwright's click is a trusted user gesture; result `ok`), then reach the panel page through `--remote-debugging-port` + `chromium.connectOverCDP` (it is not in `context.pages()` of the persistent context). Works headless: viewport 360×585, the panel auto-started the assistant, bound the fixture's window, created the provider window on the mock, and `assistant.status` returned the session. No production change. |
| d | `window.open` / `target=_blank` gives `tabs.onCreated` with `openerTabId` | **PASS** — both the new tab and the popup report the clicked mail tab as opener |
| e | The owner's real native host is unreachable from the test profile | **Changed approach (revision 2).** Facts: the owner's install registered the real host for Chromium in the default user directory; a temporary `--user-data-dir` does not consult it (two earlier read-only `status` calls to the real host name in the spike returned "host not found", which is also why those calls must not become a routine check). Chromium also reads **system-level** locations; on this Mac `/Library/Google/Chrome/NativeMessagingHosts` exists (three unrelated hosts, none ours) and the Chromium/`Application Support` system directories are absent. **Measured with a harmless test host:** a manifest placed in the *profile's own* `NativeMessagingHosts/` is consulted, and under the real host's name it answers instead of anything else (marker `E2E_FAKE_HOST`). **Mechanism to adopt:** (1) read-only preflight of the system-level candidate directories: if a manifest named like the real host is present, or a directory cannot be read (other than "does not exist"), **stop without calling anything**; (2) register a harmless fake host under the real name in the temp profile, so every native call in the tests resolves to it; (3) never call the real host as a check. **Not claimed:** anything about a worker restart. |
| f | `npm test` runs no browser; `npm run e2e` runs only E2E files | **PASS** (verified with a scratch project): bare `node --test` picks up `tests/e2e/*.e2e.test.js`, not `e2e/*.e2e.mjs`; `node --test e2e/*.e2e.mjs` runs only those |

## End-to-end loop proof (beyond the listed conditions)

With the mechanics above, against the **unmodified extension**: real Side Panel sends a prompt → the mock page receives it **with the tool contract** → the mock answers with an `inspect_page` call → the extension locks the **fixture page** (not the panel or provider tab) and runs the tool → the result, containing the fixture's title, is typed back and sent → the mock receives it. Task state afterwards: `locked` on the fixture. The only local requests were the fixture and the mock.

## What changes in the plan

1. Section 4, network: browser-level host mapping **plus** the dead proxy with a bypass list for the mock hostnames only; claim limited to the measured probe set (row b). No route-based allowlist.
2. Section 4, panel: not a tab. The **real Side Panel**, opened from a click on an extension page (`sidePanel.open({windowId})`), reached with `--remote-debugging-port` (loopback, random free port, this run's browser only) + `connectOverCDP`. The CDP port is on loopback and is itself unreachable from pages once the dead proxy is in place.
3. Section 4, native: preflight + harmless fake host under the real name in the temp profile (row e). No call to the real host, ever.
4. **S2 is narrowed to "session storage lost → the provider is found again, not duplicated".** A service-worker restart is **not covered**: it clears in-memory state (for example the `controllers` cache) but keeps `storage.session`, so clearing storage is not equivalent and is not claimed to be. The earlier "restart PASS" is withdrawn.
5. Playwright install for this harness: `PLAYWRIGHT_SKIP_BROWSER_GC=1` (documented in the install step) so other projects' cached browsers are never removed. Shared cache is kept (a dedicated `PLAYWRIGHT_BROWSERS_PATH` would download another copy).
6. Shared repository on GitHub starts **private**.
